Changes in FLTK 1.5.0                                   Released: xxx yy 2026

  This is the first FLTK release that exclusively uses CMake to be built.
  autoconf/configure/Makefile support has been removed. If you believe you
  need configure/make, then please use FLTK 1.4.x.


  Bug Fixes and other Improvements
  - Member function int Fl::get_mouse(int&, int&) has now a return value providing the
  number of the mouse-containing screen (previously, return type was void).
  - Fix rectangle drawing for wide lines on macOS Quartz
  - X11: dragging files to other applications works again: "text/uri-list"
  was announced but not served, and drop targets were flooded with
  XdndPosition messages.
  - X11: drops from Xwayland clients (e.g. Wayland applications dropping
  onto X11 windows under mutter) now finish properly.
  - Windows: fix decoding of DIB images with V4/V5 headers or bit field
  masks, and of 32-bit DIBs with unused alpha bytes, when pasting images.


  Platform Specific Fixes and Build Procedure Improvements
  - macOS: required SDK version and deployment target changed to 10.7 or higher

  Wayland related Improvements and Fixes


  Fixes and Improvements in Fluid

  - The Strings file name for internationalization can now be fully customized.
  - Bigger and clearly assigned fields for custom code for widgets.
  - New command line argument `-pr` writes files relative to the project file.

  Documentation Improvements


  Other Changes

  - Added "placeholder" text field to Fl_Input_ based widgets
  - New typed drag and drop: Fl_Drag_Data and Fl::dnd(Fl_Drag_Data*) drag
  text, images, data of any MIME type, and any number of existing or
  promised files, with drag images and copy/move/link actions.
  Drop targets can check and request the dragged types with
  Fl::dnd_contains() and Fl::dnd_request(), choose the action with
  Fl::dnd_action(), and receive images, raw data, and files promised by
  the drag source. See test/dnd.
  - Dropped files are delivered as the new type Fl::clipboard_files on all
  platforms: one decoded absolute path per line in Fl::event_text(), see
  Fl::dnd_file_count() and Fl::dnd_file(). On X11, they were previously
  delivered as URL-encoded "file://" URIs.
  - Removed autotools (configure/make) support
  - Requires C++11 or higher
